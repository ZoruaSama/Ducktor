# 术语与类型标准 · 能力 E/F

## 字段

| 字段 | 类型 | 约束 |
|---|---|---|
| symbol | 字符串 | 必填，源码真实符号名 |
| content | 字符串 | 必填，Ducktor 扩展 Markdown |
| type | 字符串 | 可选，如 class、variable、constant、enum、config；不是 anchor 的枚举 |
| scope | 字符串 | global、module、local；插件默认 global |
| block | 整数 | local 必填，blocks 原始列表的 1 基编号 |
| aliases | 字符串列表 | 可选，只用有证据且语义一致的真实别名 |
| enabled | 布尔值 | 可选，默认 true |
| tags | 字符串列表 | 可选 |

## 选择与内容

- 只解释影响理解的项目类型、业务概念、常量、配置与关键状态，不为每个变量建术语。
- 每项回答一个核心问题：这个符号是什么。优先身份、来源与当前用途，默认不超过 3 句话。
- 普通局部变量不收录；承载重要业务语义时才收录，并使用 local。
- 不重复整体流程，不将完整类实现塞入术语。
- 符号、来源、成员均须核实；仅有导入或使用代码时，只描述可确认的契约，不虚构第三方类型成员。
- 正文引用相关定义、创建函数、使用方法或文档。不得假定任意词都能跳转，也不得假定术语在说明正文中自动弹出。

## 作用域与匹配

- global：同一工作区文件夹的源文件生效，不跨工作区文件夹。
- module：仅对应源文件生效。
- local：仅绑定块重定位后的闭区间生效；禁用、无效、无法定位的块使其术语不生效。
- block 指 blocks 未过滤列表的 1 基位置，不是行号，也不是有效块列表的编号。
- 插件默认 global；生成时显式选择最小正确作用域，默认 module，不盲目使用 global。
- 只有语义在项目内确实统一、共享且不存在同名歧义时使用 global。先检查已有项目级术语，避免冲突或无意义重复。
- 匹配优先级为 symbol 完全匹配、aliases、忽略大小写；同一命中等级内 local 优先于 module，module 优先于 global。作用域不会覆盖更高关键词匹配等级。
- 不把所有 pool、config 等通用名字设成全局术语。aliases 不是模糊搜索关键词，不把不同对象当成同义词。

## L5 类型结构

默认只解释当前函数实际涉及的成员，以及理解其作用所必需的状态与协作关系，不介绍无关成员，不递归依赖树。

采用“短术语入口 → 类型源码引用 → 获准范围内的详细类型块”组织：

1. 在当前文件 terms 说明类型身份、当前用途及必要成员的简短摘要。
2. 引用已核实的类或成员定义。
3. 内容超出短术语容量时，在已获准生成范围内的类型定义处使用块 content 说明相关字段、方法契约及生命周期。定义在范围外时，先确认额外写入，或保留当前短入口与源码引用。
4. 仅在用户开启“完整类型说明”时介绍指定类型全部成员；仍不自动展开其他类型。

F 可单独启用：未启用 E 时，在获准块的 content 中介绍必要结构，不自动生成 terms。

## 示例

假设 blocks 的第 2 项对应使用连接池的函数；实际生成需重新核实。

```yaml
terms:
  - symbol: pool
    type: variable
    scope: local
    block: 2
    content: |
      当前函数使用的数据库连接池实例，由 [initDB] 创建。
      通过其连接获取方法执行数据库操作。
```

这只是 terms 片段，不是独立完整文件。实际顶层还须包含 blocks，且 block 2 必须有效。
