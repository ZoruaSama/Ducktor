# 逐行标准 · 能力 D

## 格式与定位

- `lines` 是块内对象列表，每项必有整数 `line` 与字符串 `content`。
- 使用当前源码的 1 基行号，不用 diff 行号或相对行号。
- 每项位于所属块 range 内，块内不重复，按行号升序排列。
- `range: "*"` 使用全文件行号。
- 锚点重定位时按相对块起点的偏移移动逐行位置；内部增删行仍须重新生成行号。文件末尾越界说明不会显示。
- 多个块默认不重复解释同一源码行；类结构块与方法块重叠时，只在方法或独立逻辑块提供该行的 lines。
- 保留必填整体 content。Hover 与右侧面板只展示整体说明，lines 只在独立双列预览展示。

## 覆盖要求

D 默认覆盖范围内所有有意义行，不是只覆盖关键行。应包含声明、签名、实质成员、表达式、控制流、返回、异常处理及影响理解的注释或装饰器。

- 跳过空行和纯闭合括号、分号等结构收尾。
- 对多行调用、链式操作、对象字面量、条件表达式，解释各行参数、字段或操作的具体作用；不能每行写“继续传参”。
- 解释与调用同处一行的返回、收尾动作；不能因为含括号就跳过。
- 对没有独立语义的纯分隔行可以跳过，但不能借此遗漏多行语句的参数与数据意义。
- 重要注释解释其约束及与代码的关系，不逐字改写；注释与实现不符时明确标为待核实。
- 用户明确要求稀疏关键行说明时可以生成，但报告为“关键行说明”，不能声称满足完整 D 覆盖。

## 写作要求

每项解释具体动作及其局部作用，按需要说明：操作对象、取值来源、状态变化、分支条件、数据去向。

- 差：`定义 result 变量。`
- 好：`保存 [validateToken] 的校验结果，供后续分支判断令牌是否可用。`
- 差：`执行 if 判断。`
- 好：`校验失败时进入提前返回分支，后续用户查询不会执行。`

示例中的符号须在实际生成时核实。不是每行都硬写“为什么”；只说明代码可以证明的作用，不虚构作者意图。普通动作一般 1–2 句话，复杂条件按必要信息展开，避免复述整段流程。相关符号主动提供核实过的链接。

## 示例

以下范围仅示意，不能复制为真实定位。

```yaml
blocks:
  - range: "10-15"
    anchor:
      type: function
      name: initDB
    content: |
      根据连接配置初始化连接池，并返回可供数据库操作使用的实例。
    lines:
      - line: 10
        content: |
          声明初始化入口，接收本次连接池创建所需的配置。
      - line: 11
        content: |
          校验配置中的连接参数；校验失败时不会继续创建连接池。
terms: []
```

示例是部分格式演示，不满足完整 D 覆盖。实际生成后逐项对照源码，确认每个有意义行均已覆盖。
