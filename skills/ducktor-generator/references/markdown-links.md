# Markdown 与引用标准 · Ducktor v0.5

适用于 blocks.content、lines.content、terms.content。

## 引用串联（所有等级共用）

- 解释 A 实质性提到符号 B 或实现 C 时，尽量提供已核实的引用；优先关联调用、类型定义、成员、配置来源、测试及真实文档。
- 同一段落首次实质性提及时链接，不把每次重复词都链接。逐行项可独立阅读，可分别链接同一目标。
- 先说明关联，再提供引用，如“通过 [TokenValidator.validate] 校验令牌”。不能只写“见某函数”。
- 准确优先于数量，链接不替代解释、不代表目标已有 Ducktor 说明，也不授权扩大输出范围。
- 普通局部变量不强行当成可解析符号链接；没有可确认跳转目标时用行内代码。
- 当前格式没有术语条目或解释块 ID 的直接链接。不要生成 term://、block://、自定义 ID 或未定义命令链接。
- terms 是代码关键词命中机制；不要假定说明正文中的术语能弹出术语浮窗。正文需要导航时仍使用已支持的源码或文档链接。

## 支持的链接

### 文件与源码位置

```text
[../auth.ts#12]
[../auth.ts#12-20]
[config/db.yaml]
```

路径相对于对应源码文件所在目录，不是 `.ducktor` 文件或工作区根。使用便于跨平台的 `/` 路径分隔符，核对目标存在、行号有效且解析后位于同一工作区内。例如源码 `src/main.js` 中的 `[../lib/util.js]` 指向工作区 `lib/util.js`。

### 符号

```text
[createPool]
[AuthService]
[UserService.validate]
[createPool:ts]
[UserService.validate:js]
```

插件在工作区搜索，优先函数、类、方法；多个匹配会要求选择，无匹配降级为普通文本。生成前确认目标定义，存在歧义时优先文件行范围链接。显式语言后缀只能消除部分歧义，不保证唯一。

### 文档

```text
<https://example.com/auth>
[认证流程文档](https://example.com/auth)
[限流设计](../docs/rate-limiter.md)
```

这里只是语法示例，不是实际文档。生成时使用确认的 URL 或本地路径。本地 `.md`、`.txt`、`.ducktor` 文档在编辑器打开；路径仍相对源码目录。`<认证流程文档>` 不会按标题查找，禁止这种假引用。

不要使用 `javascript:`、`data:`、`file:`。不手写插件命令链接；让插件从已支持语法生成跳转。不要把聊天中的 `file:///` 链接复制到 `.ducktor` 正文。

## Markdown 子集与扩展

- 支持加粗、斜体、粗斜体、删除线，使用行内代码包裹未链接的标识符。
- 支持 H1–H4，默认用 H3/H4；单个 content 不超过一个 H1，标题后空行，不在标题嵌套链接或样式。
- 支持无序、有序及一级嵌套列表，不建议超过两级；列表项避免标题和代码块。
- 支持行内代码、代码块、`> 引用`。代码块注明语言；只在短例子确有帮助时使用。
- Hover 不建议表格，优先短段落和列表。
- 颜色扩展 `{!red 警告}`；只允许 red、blue、green、orange、yellow、gray，用于短提示，不用任意颜色、背景、字体样式。
- 下划线扩展 `{_重要字段}`，不要嵌套链接或颜色。
- 颜色和下划线在右侧面板与独立预览生效，Hover 中会降级，不能仅用颜色表达关键含义。
- 不嵌入 HTML、CSS、脚本、图片、事件属性或 iframe；不要生成需要任意 HTML 支持的内容。
- 必要时转义正文的 Markdown 特殊字符，避免标识符中的 `_`、`*` 或反引号破坏格式；保留有意使用的 Markdown 与 Ducktor 链接，不整段盲目转义。
