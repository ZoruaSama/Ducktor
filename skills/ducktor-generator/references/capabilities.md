# 能力与等级 · 生成策略

等级是默认能力组合，不是 Ducktor YAML 字段，也不代表输出范围。先应用等级，再应用用户的增减开关。所有组合都遵守准确定位、依据充分、引用串联与内容去重。

## 能力与完成标准

| 能力 | 内容 | 完成标准 |
|---|---|---|
| A 职责概览 | 代码职责、模块角色、结果 | 不读实现也能知道处理什么、产生什么结果 |
| B 使用契约 | 重要输入输出、前提、副作用、失败行为 | 能理解如何使用及调用后影响；不机械复述类型 |
| C 执行流程 | 阶段、分支、循环、数据流、关键调用 | 能按顺序复述主要阶段和条件 |
| D 逐行说明 | 所有有意义行的动作和局部作用 | 每个有意义行均有说明，不仅选择关键行 |
| E 符号释义 | 必要类型、业务术语、配置、关键状态 | 能查明身份、来源及当前用途 |
| F 类型结构与协作 | 当前使用成员、状态、生命周期、协作关系 | 理解当前函数涉及的成员及对象关系 |
| G 审阅关注点 | 边界、错误路径、资源、并发、状态约束 | 有具体位置和依据，区分确定问题与待核实风险 |
| H 结构图示 | 流程图、框架/架构图、类图、时序图、状态图 | 图能比文字更快看清结构或流转，关系与源码一致，关键节点可跳转源码 |

A/B/C/G/H 主要写入块 content（H 也可写入 terms content），D 写入 lines，E 写入 terms。H 的语法与限制见[图表标准](diagrams.md)。F 在短术语中提供相关成员摘要，较长内容放到获准生成范围内的类定义解释块；不要发明新字段。

## 递进预设

| 等级 | 名称 | 默认能力 |
|---|---|---|
| L1 | 概览 | A |
| L2 | 使用 | A + B |
| L3 | 理解 | A + B + C |
| L4 | 逐行 | A + B + C + D |
| L5 | 导学 | A + B + C + D + E + F |

G 与 H 是独立开关，不要求升到 L5。H 不属于任何等级的默认能力：用户明确要求图表时启用；未明确要求时，仅在已启用 C、E 或 F 且满足下方“何时创建图表”条件时按需使用，并在报告中说明。用户明确禁用图表时不创建。允许 L1 + E、L4 + G、L3 + E 等组合。禁用 D 后不得宣称提供完整逐行说明。F 未启用 E 时仍可在获准范围的块 content 中解释相关成员，不自动重新开启 E。

L5 默认只解释当前函数涉及的成员；“完整类型说明”作为按需开关，必须由用户明确开启，并限定类型和输出范围。它只扩大指定类型的成员介绍，不递归扩展所有依赖。

## 各能力写作边界

- A：以职责和结果开头，不提前堆执行细节。概览一般为 1–3 句话，复杂职责可用短列表。
- B：只列影响使用的重要契约；区分返回、抛错、异步拒绝与内部捕获。区分返回新对象和修改传入对象。
- C：按逻辑阶段写，不按源码句数写；说明条件及数据如何变化，不虚构设计动机。
- D：逐行关注操作对象、计算、条件、状态和结果，与整体阶段说明互补。
- E：只解释影响理解的陌生符号；不把普通循环变量或全部内置类型纳入术语。
- F：说明相关字段的语义、使用方法的契约及必要协作；不抄完整类声明。
- G：以“行为/条件 → 可能后果 → 核对位置”组织。有证据的缺陷明确说明，推测风险标为待核实，不借生成解释擅自修代码。
- H：图是文字的补充，不替代文字；图前先用文字给出结论，因 Hover 与逐行预览不渲染图表。只画源码可证实的关系。

## 何时创建图表（H）

适合创建：

- 流程图：多阶段、多分支、提前返回、循环重试或跨函数调用链，文字需按顺序列出 4 个以上步骤或 2 个以上分支时。
- 框架/架构图（flowchart + subgraph）：模块或文件级概览中，多个组件/层之间存在依赖或数据流向时，常见于 L1 项目或模块概览。
- 类图：F 涉及 3 个以上相互协作的类型，或存在继承、实现、组合关系需要一眼看清时。
- 时序图：多个对象或服务之间存在有顺序的请求/回调/异步消息往返时。
- 状态图：对象有明确状态字段及多个状态迁移条件时。

不要创建：

- 线性、短小、一两句话能讲清的逻辑；简单 getter/setter、纯数据定义。
- 只是把文字列表换成方框、没有结构增量的图。
- 关系依赖推测、无法从源码核实时。
- 每个块都附图；同一模块内重复画相同结构。优先在最高层概览块放一张主干图，细节块用文字和引用。
- 内容写在 `lines` 中时。

图中关键节点需要跳转实现时，用 `ducktor-link` 绑定到当前源码行范围；类图与流程图优先，时序图与状态图的跳转放在图外普通引用。

## 组合示例

- 整个项目快速浏览：L1，输出职责概览，不加逐行实现。
- 陌生项目概览并查术语：L1 + E。
- AI 改动 review：L4 + G，范围为包含改动的函数或逻辑单元与必要上下文。
- 学习当前模块：L5，不因查阅类型而自动为全仓库生成解释。
- 理解陌生模块架构：L1 + H，在模块入口块放一张带源码跳转的框架图。
- 复杂流程 review：L4 + G + H，在函数块中用流程图标出分支与错误路径。

不用每个块都填固定栏目。依据源码复杂度与实际能力选择短段落、标题或列表；避免“输入：无、输出：无、异常：无”一类无意义模板。
