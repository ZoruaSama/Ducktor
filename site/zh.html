为真实的代码阅读而设计

增加上下文，不增加干扰。

无论是熟悉陌生项目、追踪具体实现，还是审阅改动，解释都保存在镜像的 .ducktor 文件中，不必修改源码。

快速开始

让下一个代码库，更容易读懂。

让 Agent 帮你安装

复制以下提示词到 Agent，让它先确认安装目标，再执行全局安装：

请帮我安装 Ducktor skill 和 VSIX 插件，仓库：https://github.com/ZoruaSama/Ducktor。
1. 先检测操作系统及本机已安装的 VS Code 类 IDE（如 VS Code、Cursor、Qoder、Trae、CodeBuddy 等），列出名称、版本及可用的 CLI 或安装路径。不要假定只安装了 VS Code。
2. 询问我想给哪个或哪些 IDE 安装插件，以及使用哪个或哪些 Agent；等我确认后再安装。
3. skill 必须安装到用户主目录下的全局路径，不要安装到项目目录。手动安装时完整复制 skills/ducktor-generator/（含 SKILL.md 和 references/）到所选 Agent 的全局目录：Codex 用 ~/.codex/skills/ducktor-generator/，Claude Code 用 ~/.claude/skills/ducktor-generator/，Cursor 用 ~/.cursor/skills/ducktor-generator/。
4. 若使用 OpenSkills，先检查 Node.js/npm，按需安装 npm install -g openskills，再运行 openskills install ZoruaSama/Ducktor --global --universal，选择 ducktor-generator。确认所选 Agent 能加载 ~/.agent/skills/；不能自动加载时，使用其原生全局 skill 目录。后续更新用 openskills update ducktor-generator。
5. 从 GitHub Releases 下载最新发布的 VSIX，使用所选 IDE 实际支持的安装方式安装到当前用户的全局扩展目录，不要装到项目或其他 IDE。不要覆盖已有设置；需要新增依赖、提权或覆盖文件时先征求我确认。
6. 验证插件已安装、skill 的 SKILL.md 和 references/ 完整可读，报告实际安装路径及需要重启或重新加载的 IDE/Agent。不要声称尚未执行的步骤已成功。
7. 最后向用户输出以下使用提示：
按 Ctrl + Shift + P（macOS：⌘ + Shift + P）打开命令面板，直接搜索以下关键词，选择对应的切换命令并确保功能已开启：
hover：开启 Hover 悬浮提示。
codelens：开启 CodeLens。
inlay hints（或 inline hints）：开启 Inlay Hints 行内提示。

自己手动安装

1. 安装 VS Code 插件

Ducktor 暂未发布到 VS Code 插件商店。请从 GitHub Releases 下载最新的 .vsix 文件，在 IDE 命令面板运行 Extensions: Install from VSIX...，选择下载的文件完成安装。

从 Releases 下载 VSIX ↗体验交互预览 →

在 VS Code 中打开项目文件夹，按 Ctrl + Shift + P（macOS：⌘ + Shift + P）打开命令面板，直接搜索以下关键词，选择对应的切换命令并确保功能已开启：

  • hover：开启 Hover 悬浮提示。
  • codelens：开启 CodeLens。
  • inlay hints（或 inline hints）：开启 Inlay Hints 行内提示。

也可以打开命令面板，搜索 Preferences: Open User Settings (JSON)，将以下配置合并到现有设置（不要覆盖其他配置）：

{
  "editor.inlayHints.enabled": "on",
  "editor.hover.enabled": true,
  "editor.codeLens": true
}

2. 安装生成 skill

使用 OpenSkills：用 OpenSkills 安装完整 skill。先安装 Node.js LTS（包含 npm），在终端安装 OpenSkills：

npm install -g openskills

全局安装到用户主目录的通用 Agent skill 路径（~/.agent/skills/）：--global 表示全局安装，--universal 表示使用通用目录；仅加 --universal 不会变成全局安装。

openskills install ZoruaSama/Ducktor --global --universal

后续更新此 skill：

openskills update ducktor-generator

如 Agent 通过 AGENTS.md 加载 skill，可在对应项目运行以下注册命令（不会将 skill 重新安装到项目）：

openskills sync

出现提示时选择 ducktor-generator。sync 为读取 AGENTS.md 的 Agent 注册 skill；其他Agent遵循各自的加载约定。

手动安装：下载或克隆本仓库，将 skills/ducktor-generator/ 整个目录复制到Agent 的 skill 路径，包含 SKILL.md 和 references/。

  • Codex：~/.codex/skills/ducktor-generator/
  • Claude Code：~/.claude/skills/ducktor-generator/
  • Cursor：~/.cursor/skills/ducktor-generator/

以上为用户主目录（~）下的全局 skill 路径，不是项目目录。按Agent要求重启或重新加载 Agent；若未自动发现 skill，可让 Agent 读取克隆仓库中的 skills/ducktor-generator/SKILL.md 并遵循其流程。

安装完成后，可向 AI Agent 发出生成请求：

为 src/main.js 生成 L3 Ducktor 解释，
使用中文，并为相关符号补充
可核实的引用。

使用前的小提示

几个实用问题。

插件会自动生成解释吗？

不会。生成由使用 Ducktor generator skill 的 AI Agent完成。插件只读取和展示已有解释，无需配置模型或 API Key。你也可以手写解释文件。

解释文件应该放在哪里？

在工作区根 .ducktor/ 目录下镜像源码路径，再追加 .ducktor 扩展名。例如 src/main.js 对应 .ducktor/src/main.js.ducktor。插件不读取源码旁的解释文件；多根工作区中的每个文件夹分别维护解释目录。

怎样打开不同的阅读视图？

悬停 Ducktor 行末提示或带下划线的术语；存在有效逐行解释时，使用文件顶部的 CodeLens。浏览项目可在命令面板运行 Ducktor: Open File Explorer / 打开文件目录。将 ducktor.displayMode 设为 panel 可使用右侧面板。

可以生成中文解释吗？

可以。在生成请求中明确正文语言。将 ducktor.language 设为 zh-CN 可使用插件的中文界面；该设置不会翻译已有解释正文。
